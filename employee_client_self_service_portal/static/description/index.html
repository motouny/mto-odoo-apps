Why this app

Odoo's own Employee and Time Off apps require an internal user license. If most of your workforce only ever needs to check a leave balance, request time off, or clock in and out, this app gives them everything they need through the free Portal user type instead — no extra license required.

On top of that, if some of your projects are overseen by an external contact (a client, a site manager, a department head) who isn't an Odoo user at all, this app gives that person a lightweight, project-scoped Portal Manager role: they can see their project's team status for the day and approve time-off requests, entirely from the portal, with zero Odoo licenses on their side either.

And for everything that isn't a leave request — a permission, an attendance correction, an overtime claim, a letter, an equipment request, an internal support ticket, or a genuine external client service request — the built-in request system gives both employees and true external clients a single place to submit, track and comment on their own requests, with a full audit trail and in-portal notifications.

What employees get under /my

My Profile Edit private contact and emergency information.
My Time Off See remaining balance, submit and cancel leave requests, follow the approval stage live.
My Attendances Check in / check out and review monthly attendance from the portal.
My Tasks Read-only list of Project tasks assigned to the employee.
My Assignments Accept lightweight tasks assigned by the project's Portal Manager, post status updates, get a daily email reminder until marked done.
My Requests Submit permission, attendance correction, overtime, letter, data change, equipment or internal support requests, and track each one through to closure.
Notifications In-portal notifications every time one of your requests changes status.

What a project's Portal Manager gets

My Team Card-grid of the project's employees with today's status: present, on leave, on permission or absent.
Approvals First-stage approval on the team's time off / permission requests before internal HR finalizes them.
Team Tasks Assign lightweight tasks with a deadline to the project's employees and track progress.

What a true external Client gets (new, separate role)

A dedicated Client group — distinct from the project-scoped Portal Manager above — lets an external company contact submit and track their own service requests under /my/requests, without ever seeing any employee HR data. Every request is looked up strictly by ownership; a client can never see another client's request, and an employee can never see a client's request either.

What your staff get in the backend

All Requests Every employee and client request in one queue, with pivot/graph reporting by type, status and assignee.
My Tickets / Overdue Quick filters for what's assigned to you and what's past its due date.
Request Types & Teams Configure your own request categories and the teams that handle them.

Built for multi-tenant, license-conscious, multi-company deployments

  • Only two new security groups: Client (external self-service) and Request Manager (internal triage staff) — the existing employee and Portal Manager flows still run on the standard Portal user type.
  • Branding follows your own company name and logo automatically; no fixed color scheme is imposed.
  • The Portal Manager role is assigned per project, so a single client contact can oversee exactly the employees working on their project — nothing else — and this is now correctly scoped per company too.
  • Two-stage time-off validation: the client-side Portal Manager approves first, then your internal HR finalizes it — the client is never the final word.
  • The request status history is immutable — not even an administrator can edit it through the UI.
  • Ships in English and Arabic.

Setup

  1. Install the module.
  2. On an hr.employee record, use the Grant Portal Access button to create (or link) a portal user for that employee.
  3. On a project.project, set the Portal Manager field to the portal user who should oversee that project's employees.
  4. On each hr.employee working on that project, set Portal Project to the same project.
  5. Under Settings → Users, assign the Client group to any external contact who should get their own request self-service area, and Request Manager to the internal staff who will triage requests.
  6. Done — employees see their self-service tiles (including My Requests) at /my, the Portal Manager sees a "My Team" tile, and clients land directly on their own request list.
